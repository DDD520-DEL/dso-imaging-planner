# 深空天文摄影规划工作台

一个前后端一体的深空摄影规划工具：光学采样与视场、曝光与信噪比估算、目标可见性、跟踪精度校核，
以及「今夜拍摄排程」（按当夜天文夜排出带换目标/换滤镜开销的时间线、窗口与月光告警、未排入清单和利用率），
「器材齐套」校核（光路链路长度累加 vs 主镜要求后截距、转接环组合建议、螺纹接口逐节匹配、整套重量 vs 赤道仪载重余量、导星采样比），
配一个可增删的自定义目标库。

项目**不依赖任何第三方 npm 包**，全部使用 Node 内置能力（`node:http`、`node:fs`、`node:test`），
clone 后即可直接运行和测试，也不需要数据库。

## 运行

```bash
npm start
```

打开 `http://localhost:5175`。页面右上角会显示接口在线状态，填好参数点「开始规划」会一次性调用四类计算接口；
左侧「今夜拍摄排程」单独点「排定今夜时间线」调用排程接口。
端口可通过环境变量覆盖，例如 `PORT=8080 npm start`。

## 测试

```bash
npm test
```

测试分六层：

- `test/optics.test.js`：像素尺度、传感器画幅、视场角、焦比、道斯/衍射极限、采样分级
- `test/exposure.test.js`：天光通量、单帧与叠加信噪比、天空背景主导曝光、饱和时间、目标信噪比反解
- `test/visibility.test.js`：中天高度、可观测时长（含恒显与不可见）、天文夜、午夜高度、月相
- `test/tracking.test.js`：星点 FWHM 合成、跟踪分级、极轴漂移率与允许极轴误差反解
- `test/schedule.test.js`：正常排布（优先级、切换开销、互不重叠、利用率）、窗口不足告警与未排入、完全排不下（无天文夜/整夜不升起/总需求超载）
- `test/train.test.js`：正好合焦、差一点需加转接环（组合与余量）、链路超长、接口不匹配、超重、导星采样比分级、结构与字段校验
- `test/api.test.js`：启动真实 HTTP 服务，验证健康检查、首页与样式、六类计算接口、目标库增删查重、错误处理与路径越界

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 服务健康检查 |
| GET | `/api/targets` | 返回内置目标与自定义目标 |
| POST | `/api/targets` | 新增自定义目标，body 为 `name`/`raHours`/`decDeg`/`magnitude`/`sizeArcmin`/`category` |
| DELETE | `/api/targets/:id` | 删除自定义目标；内置目标不可删除 |
| POST | `/api/optics/report` | 光学采样与视场计算 |
| POST | `/api/exposure/estimate` | 曝光与信噪比估算 |
| POST | `/api/visibility/plan` | 目标可见性规划 |
| POST | `/api/tracking/check` | 跟踪精度校核 |
| POST | `/api/schedule/plan` | 今夜拍摄排程，body 为 `latitude`/`dayOfYear`/`date`/`minAltitude`/`targetSwitchMinutes`/`filterSwitchMinutes`/`moonThreshold` 与 `targets[]`（`name`/`raHours`/`decDeg`/`exposureMinutes`/`priority`/`filter`） |
| POST | `/api/train/check` | 器材齐套校核，body 为 `payloadMarginKg` 与 `items[]`（`type`/`name`/`weightG` 加各类型字段：`ota` 要 `focalLengthMm`/`requiredBackfocusMm`/`threadRear`，`focuser`/`filterWheel`/`adapter` 要 `lengthMm`/`threadFront`/`threadRear`，`camera` 要 `lengthMm`（法兰距）/`pixelSizeUm`/`threadFront`，`guider` 要 `guideFocalLengthMm`/`guidePixelSizeUm`） |

四类计算接口的请求体与页面输入一一对应，参数越界或缺字段返回 `400`，响应体形如 `{ "error": "参数「焦距（mm）」不能小于 50，当前为 10" }`。

## 计算模型与口径

这套模型用于横向比较配置与曝光参数，结论按下述口径复现：

- **像素尺度**：`206264.806 × 像元尺寸(mm) ÷ 焦距(mm)`，单位 ″/px；视场角按 `2·atan(画幅 ÷ 2f)` 计算。
- **采样判定**：像素尺度与视宁度之比落在 `1/3 ~ 1/2` 判为「接近理想」，小于 `1/3` 为「过采样」，大于 `1/2` 为「欠采样」。
- **衍射极限**：`1.22λ/D`，默认参考波长 550 nm；道斯极限取 `116 ÷ 口径(mm)`。
- **像素天光通量**：以 21.5 mag/arcsec²、口径 100 mm、1.5 ″/px、透过率 0.8、量子效率 0.6 时约 8.5 e-/s/px 标定的相对模型，输出正比于口径面积、像素天区面积与亮度的 `10^(-0.4Δmag)`。
- **信噪比**：单帧 `S/√(S + D·t + R²)`，N 帧叠加按信号 `N·S`、方差 `N·(S + D·t + R²)` 合成；天空背景主导曝光取「天光信号达到读出噪声方差 10 倍」的时长。
- **可见性**：中天高度 `90 − |纬度 − 赤纬|`；可观测时长由最低可用高度角反解时角窗口；天文夜按太阳高度 −18° 近似。
- **午夜高度**：以太阳反照点赤经作为午夜中天赤经的近似，再由时角求目标高度。
- **月相**：以 2000-01-06 18:14 UTC 的新月为起点，按 29.530588853 天的朔望月周期计算月龄与照亮比例，不引入观测者地理经纬度。
- **今夜排程**：以目标中天对齐太阳反照点赤经、可观测时长半宽向前后展开，得到每个目标相对当地午夜的可观测条带，再与当夜天文夜（太阳 −18°，昏影终到晨光始）取交。按优先级（1 最高，同序按输入顺序）逐个接纳目标；每接纳一个就对全部已接纳目标整体重排——按窗口结束时刻升序（最早落没的傍晚目标先占傍晚天空，即带释放/截止时间单机排布的 EDD 次序）选最靠前空档，贪心无解时再用受限回溯兜底，因此**高优先级目标加入时，已排好的低优先级目标会自动让位到更晚的空档**，不会被高优先级目标的早期贪心位置锁死；真正无法共存时只拒绝当前最低优先级目标。每段曝光前计入「换目标开销」，滤镜与时间上紧前一段不同时再加「换滤镜开销」。排不下的目标进入未排入清单（`no-window`/`window-too-short`/`no-capacity`/`no-astronomical-night`/`invalid-target`），`no-capacity` 会报告让位后窗口内的**最长连续空档**与占用该窗口的高优先级目标，而不是笼统地报整段窗口长度。利用率 = 曝光时长 ÷ 天文夜时长，切换与空闲单独列出。时间均为相对当地午夜的时钟时刻（负值为前一日傍晚）。
- **跟踪校核**：星点 FWHM 由视宁度与跟踪误差的平方和合成（σ→FWHM 系数 2.355）；极轴偏差 `θ` 引起的赤纬漂移率按 `15°/h × sinθ` 近似，并按单帧漂移不超过 1 像素反解允许的极轴误差。
- **器材齐套**：链路总长 = 调焦座/滤镜轮/转接环占位 + 相机法兰距（主镜为基准面不占长度，导星设备不进光路）；合焦差额 = 要求后截距 − 链路总长，偏差不足 0.5 mm 时两个方向（缺一点或超一点）都由调焦行程吸收、判正好合焦；缺口 ≥ 0.5 mm 时按标准转接环厚度（20/10/5/3/2/1/0.5 mm，可复用）向下精确拼组，拼组后不足 0.5 mm 的余量同样交调焦行程吸收；超出 ≥ 0.5 mm 才判「链路超长」。螺纹接口按「同规格 + 内外互补」逐节匹配（卡口同规格互配），接不上、超长、超重都作为 `problems` 明确列出而不是静默通过。导星采样比 = 导星像素尺度 ÷ 主镜像素尺度，≤2 判「充裕」、≤4 判「可用」、再大判「偏大」。

## 目标库

内置 10 个常见深空目标（M31、M42、M45、M51、M81、M101、M13、M8、NGC 7000、IC 1396），只读；
自定义目标通过界面或 `POST /api/targets` 写入 `data/targets.json`，删除后立即从列表移除。
目标库里的「用于可见性」按钮会把赤经赤纬填进左侧可见性参数，「加入排程」会把目标追加到今夜排程目标表。

目标记录字段：`name`（必填，≤40 字）、`raHours`（0–24）、`decDeg`（−90–90）、`magnitude`（可选）、`sizeArcmin`（可选）、`category`（可选）。
